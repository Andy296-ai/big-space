# Nodus — Infinite Space

Полная справка по проекту: что это, из чего собрано, как устроено и как запускать. Писалось как личный справочник, чтобы не забыть детали архитектуры и принятые решения.

Дата снимка: 2026-08-14.

---

## 1. Что это

Nodus (кодовое имя репозитория — `laravel_infinite_space`) — веб-приложение для построения и совместного ведения "бесконечных" графов узлов: деревьев/сетей заметок, проектов, связей людей и пространств — с 2D-канвасом, живым совместным редактированием, комментариями, историей изменений и админкой на несколько пользователей.

Ключевая метафора: **Space** (пространство) содержит **Nodes** (узлы) и **Edges** (связи между ними). У пространства есть владелец, но им можно поделиться с другими пользователями с ролью viewer/editor.

---

## 2. Технологический стек

- **Backend**: Laravel 13 (стиль `bootstrap/app.php`, без `Kernel.php`), PHP.
- **Frontend**: Inertia.js + Vue 3 (`<script setup>`, TypeScript) + Tailwind CSS.
- **Рендер графа**: собственный canvas-рендерер (`SpaceScene.vue`) — без сторонних графовых библиотек, ручной `requestAnimationFrame`-цикл, ручные world↔screen трансформации.
- **База данных**: PostgreSQL (рекомендуется, легко переносится между серверами через `pg_dump`/`pg_restore`, держит параллельную запись под нагрузкой); SQLite остаётся вариантом для быстрого локального пробного запуска (`DB_CONNECTION=sqlite` в `.env`).
- **Живое обновление**: Laravel Reverb (свой WebSocket-сервер, протокол Pusher) + Laravel Echo на фронте. Presence-каналы для "кто сейчас смотрит" и живых курсоров (whisper-события, без похода на сервер).
- **Тесты**: Pest (backend), Vitest (frontend utils).
- **Статический анализ**: PHPStan/Larastan (уровень 7), Pint (форматирование PHP), ESLint + Prettier (фронт), vue-tsc (типы).
- **Десктопный клиент**: Tauri (Rust) — тонкая обёртка-webview, см. раздел 10.

## 3. Архитектура

### 3.1 Backend — контроллеры

| Контроллер | Назначение |
|---|---|
| `GraphController` | Граф целиком: CRUD узлов/рёбер, перемещение (одиночное и bulk), копирование поддерева, удаление с каскадом и undo-токеном, логотипы узлов, история ревизий узла. |
| `SpaceController` | CRUD пространств, экспорт/импорт, смена структуры графа (tree/dag/network/leveled). |
| `SpaceCollaboratorController` | Шеринг пространства: добавить/изменить роль/забрать доступ. |
| `NodeCommentController` | Комментарии на узле (viewer тоже может писать). |
| `NodeTreeSettingsController` | Настройки дерева на корневом узле: форма/цвет по умолчанию для новых узлов + разовое применение ко всем существующим. |
| `SpaceActivityLogController` | Лента изменений одного пространства (владелец/root). |
| `NotificationController` | Личные уведомления пользователя (список, отметить прочитанным). |
| `SearchController` | Поиск по всем пространствам пользователя (заголовки, теги, содержимое вложений). |
| `AttachmentController` | Файлы/ссылки на узлах: загрузка, скачивание, превью, полнотекстовый поиск по содержимому. |
| `Admin\UserController` | root-only: создание/удаление пользователей, сброс пароля — представлены как узлы в служебном Admin-пространстве. |
| `Admin\ActivityLogController` | Глобальная лента действий root'а. |
| `AuthController` | Логин/логаут (поле для входа называется `username`, матчится на колонку `name`). |

### 3.2 Backend — модели и связи

- **Space** — `belongsTo User` (owner), `hasMany Node/Edge`, `belongsToMany User` через `space_collaborators` (кастомный pivot `SpaceCollaboratorPivot` с ролью). Поле `structure`: `tree | dag | network | leveled`.
- **Node** — `belongsTo Space`, `hasMany NodeAttachment/NodeRevision/NodeComment`, `belongsToMany Node` (parents/children через таблицу `edges`), `tree_root_id` — денормализованная ссылка на корень своего дерева (пересчитывается `GraphRepository::updateTreeRootIds()`). Поля `default_shape`/`default_color` — только у корневых узлов (depth=0), используются как дефолт для новых детей дерева.
- **Edge** — `parent_id`/`child_id`, привязано к `space_id`.
- **NodeAttachment** — файл (в приватном storage) или внешняя ссылка.
- **NodeRevision** — снимок узла перед правкой, максимум 50 на узел (старые вытесняются).
- **NodeComment** — обсуждение на узле, `user_id` нулится при удалении автора (`nullOnDelete`), комментарий переживает удаление автора.
- **ActivityLog** — неизменяемый журнал действий; `space_id` nullable (null = admin-уровневое событие вроде создания пользователя, не привязанное к пространству).
- **SpaceCollaborator** / **SpaceCollaboratorPivot** — роль `viewer`/`editor` на паре (space, user).
- **User** — `is_root` даёт универсальный доступ везде (обходит все Policy-проверки). `use Notifiable` — для уведомлений через стандартный Laravel notifications-стек (только `database`-канал, см. ниже почему).

### 3.3 Авторизация

`SpacePolicy` с тремя уровнями:
- **access** — просмотр (owner, root, любой коллаборатор независимо от роли).
- **edit** — менять граф (owner, root, коллаборатор с ролью `editor`).
- **manage** — удаление пространства, шеринг, лента изменений пространства (только owner и root).

Middleware `can:access,space` / `can:edit,space` / `can:manage,space` навешаны группами в `routes/web.php`.

### 3.4 Живой синк (Reverb)

Философия: **"сигнал без пейлоада, клиент перезапрашивает"** — события не тащат диффы, только "что-то изменилось у X" или "у тебя новое Y", а фронт сам делает `GET` заново. Так проще гарантировать консистентность, чем городить патчинг.

- `SpaceUpdated` (`ShouldBroadcastNow`) — канал `space.{id}`, событие `.space.updated`. Шлётся при любом создании/апдейте/удалении узла (хуки в `Node::booted()`), а также вручную из мест, где меняющие запросы идут через query builder (`bulkMove`, `deleteNodes` и т.п. — там модельные хуки не срабатывают).
- `CommentPosted` — тот же канал, отдельное имя события `.comment.posted`, чтобы открытая панель комментариев могла перезапросить только комментарии, не весь граф.
- `NotificationPosted` — канал `App.Models.User.{id}` (стандартный Laravel-канал для приватных уведомлений пользователя), событие `.notification.posted`.
- Presence-канал `space.{id}.presence` — кто сейчас смотрит пространство + живые курсоры через `whisper` (не долетают до сервера вообще, чистый peer-broadcast через Reverb).

**Важная деталь:** уведомления НЕ используют встроенный Laravel-канал `broadcast` для нотификаций — он всегда уходит через очередь (`BroadcastNotificationCreated implements ShouldBroadcast`, не `ShouldBroadcastNow`), а очередь (`QUEUE_CONNECTION=database`) в проекте никто не воркерит. Поэтому `SpaceAccessGranted` использует только `database`-канал (обычная запись в БД), а "живой" сигнал о новом уведомлении шлётся отдельным лёгким `NotificationPosted`-событием.

### 3.5 Frontend — структура

- `resources/js/pages/Welcome.vue` — главная страница-оркестратор: держит состояние графа, все модалки, обработчики хоткеев, живые подписки.
- `resources/js/components/SpaceScene.vue` — канвас. Источник истины для расшаренных TS-интерфейсов графа (`NodeData`, `EdgeData`, `CameraState`, `PresenceUser`, `RemoteCursor`, `NodeShape`) — остальные файлы импортируют типы отсюда, а не наоборот.
- `resources/js/components/HudOverlay.vue` — верхняя панель (переключатель пространства, поиск, кнопки лент/настроек/уведомлений, статистика, Auto-Organize).
- `resources/js/utils/layoutEngine.ts` — 8 алгоритмов авто-раскладки (`hierarchy`, `spiral`, `rings`, `grid`, `radial`, `layered`, `cluster`, `force`). `hierarchy` (дефолтный) с 2026-08-14 привязывает каждое дерево к его собственной текущей позиции корня, а не сбрасывает всё на одну общую ось.
- `resources/js/types/settings.ts` — вся система настроек + переводы (4 языка: en/ru/tg/fa) + `TranslationKeys` интерфейс, который держит их в синхронизации на уровне типов.
- `resources/js/lib/i18n.ts`, `resources/js/lib/api.ts` (обёртка fetch с CSRF), `resources/js/lib/echo.ts` (синглтон Echo-клиента).

### 3.6 Взаимодействие с канвасом

- Левая кнопка + перетаскивание узла — двигает **только этот узел** (дети остаются на месте, рёбра просто тянутся к новой точке).
- **Правая кнопка** + перетаскивание — двигает узел **вместе со всем его поддеревом**, жёстко (форма поддерева не ломается). Перетаскиваемое дерево не прилипает к курсору 1:1 — целевая точка обновляется от курсора, а фактическая (отрисовываемая) позиция каждый кадр слегка её догоняет (пружинный эффект, тот же приём, что и у камеры).
- **Магнитное расталкивание**: если перетаскиваемое поддерево подходит слишком близко (< 130 мировых единиц) к узлам чужого дерева, то чужое дерево целиком плавно отодвигается в сторону — тоже с анимацией, не мгновенным скачком.
- Правый клик по канвасу не открывает системное контекстное меню браузера (`@contextmenu.prevent`).
- **Auto-Organize** пересчитывает раскладку выбранным алгоритмом, но (для `hierarchy`) не сбрасывает деревья на общую ось — каждое остаётся у своего текущего корня; деревья с одинаковым (обычно дефолтным 0,0) якорем раздвигаются, чтобы не наложиться друг на друга.

## 4. Инвентарь фич

### Граф и узлы
- Создание корневых узлов и детей, редактирование, копирование поддерева, удаление с превью каскада и undo-токеном (снимок на час в кэше).
- Форма (5 вариантов), цвет, логотип, теги, описание, координаты на карте (Yandex Maps), вложения (файлы и ссылки, с превью и полнотекстовым поиском по содержимому txt/md).
- Перетаскивание: одиночное (левая кнопка) и поддеревом с магнитным расталкиванием (правая кнопка), 8 алгоритмов авто-раскладки.
- История правок узла (до 50 снимков) с восстановлением любой версии.
- Блок "Связи" в панели узла — родители/дети с переходом по клику.
- Панель настроек дерева (только у корневых узлов) — дефолтная форма/цвет для новых узлов дерева + кнопка "применить ко всем" (ретроактивно, включая сам корень).

### Совместная работа
- Шеринг пространства с ролями viewer/editor.
- Presence — кто сейчас смотрит пространство, живые курсоры других участников.
- Живой синк графа между вкладками/пользователями без перезагрузки.
- Комментарии на узлах (доступны viewer'ам, удаление — автору или owner/root).
- Уведомление "вам открыли доступ к пространству" — колокольчик с бейджем непрочитанных, живое обновление, клик переносит в нужное пространство.
- Лента изменений пространства (для owner/root) — создание/удаление узлов, изменения связей/структуры, шеринг.

### Поиск и навигация
- Глобальный поиск по всем своим пространствам (заголовки, описания, теги, содержимое вложений).
- Локальные фильтры (глубина, теги, даты создания, только листья).
- Хоткеи (список — в `SettingsPanel.vue`).
- Мини-карта.

### Админка (root)
- Пользователи и чужие пространства представлены как узлы в служебном Admin-пространстве.
- Создание/удаление пользователей, сброс пароля.
- Глобальная лента действий root'а.
- root имеет универсальный доступ ко всем пространствам в обход всех Policy.

### Экспорт/импорт
- Экспорт пространства целиком (файл со своей нумерацией узлов, не завязан на id из базы).
- Импорт такого файла.

### Безопасность
- CSRF через cookie `XSRF-TOKEN` + заголовок (обёртка `apiFetch`).
- Security-заголовки (см. историю коммитов на эту тему).
- SQL LIKE-паттерны в поиске экранируются вручную (SQLite не эскейпит `\` в LIKE по умолчанию, в отличие от MySQL).

## 5. API-поверхность (кратко)

Всё под `/api`, требует `auth` middleware.

```
GET/POST   /spaces
POST       /spaces/import
GET        /search
GET/POST   /notifications, /notifications/{id}/read, /notifications/read-all
POST/PUT/DELETE /admin/users...            (root only)
GET        /admin/activity-log             (root only)

# внутри /spaces/{space}, can:access,space
GET  /export, /graph, /nodes/{n}/logo, /attachments/search
GET  /nodes/{n}/attachments/{a}/{download|preview|content}
GET  /nodes/{n}/deletion-preview, /nodes/{n}/revisions
GET/POST/DELETE /nodes/{n}/comments...

  # can:edit,space
  PUT  /structure
  POST /nodes/root, /nodes/{parent}/child, /nodes/{n}/copy
  PUT  /nodes/bulk-move, /nodes/{n}/move, /nodes/{n}, /nodes/{n}/tree-settings
  POST /nodes/{n}/logo, /nodes/{n}/attachments
  PUT  /nodes/{n}/attachments/{a}/content
  DELETE /nodes/{n}/attachments/{a}
  POST/DELETE /links
  POST /nodes/delete-many, /nodes/restore, /nodes/{n}/revisions/{r}/restore

  # can:manage,space
  DELETE /                                  (удалить пространство)
  GET    /activity-log                      (лента этого пространства)
  GET/POST/PUT/DELETE /collaborators...
```

## 6. Локальный запуск

### Требования
PHP (с расширением `pdo_pgsql`) + Composer, Node/npm, PostgreSQL (роль + база, см. `.env`). Для быстрого пробного запуска подойдёт и SQLite — `DB_CONNECTION=sqlite`, остальные `DB_*` не нужны.

### Быстрый старт
```bash
./dev.sh          # поднимает php artisan serve (:8000) + reverb:start (:8080) + vite
```
Порт бэкенда переопределяется: `PORT=8123 ./dev.sh`. `Ctrl+C` останавливает все три процесса разом.

### Ключевые переменные `.env`
```
APP_URL=http://localhost:8000
SESSION_DRIVER=database
BROADCAST_CONNECTION=reverb
REVERB_HOST=localhost
REVERB_PORT=8080
REVERB_SCHEME=http
QUEUE_CONNECTION=database   # но воркер никто не запускает — см. §3.4 про уведомления
```

### Тесты и проверки
```bash
php artisan test              # Pest, backend
vendor/bin/pint --test        # стиль PHP
vendor/bin/phpstan analyse --memory-limit=512M

npx vitest run                # frontend utils
npx vue-tsc --noEmit
npx eslint resources/js --max-warnings=0
npx prettier --check resources/js
```
На момент этого снимка: 137 backend-тестов (Pest), 33 frontend-теста (Vitest), всё зелёное.

## 7. Устоявшиеся соглашения кодовой базы

- **Комментарии в коде — только на русском**, только там, где неочевидна ПРИЧИНА (скрытое ограничение, обход бага, инвариант) — не что делает код.
- **i18n**: любая новая пользовательская строка добавляется в `TranslationKeys` + все 4 языковых блока в `settings.ts`, обычно рядом с похожим существующим ключом.
- **Тесты**: глобальные хелперы объявляются прямо в файле теста (например `createMirroredUserAndSpace()`), а не в отдельном хелпер-файле — так сложилось в проекте.
- **Broadcast-события**: `ShouldBroadcastNow` (не через очередь), "сигнал без данных, клиент перезапрашивает" — см. §3.4.
- **Bulk-операции над позициями узлов** всегда идут через `PUT /nodes/bulk-move` одним запросом, а не N штук поодиночке (так делает и Auto-Organize, и правое перетаскивание поддерева).
- **Модальные окна** — паттерн: `<Teleport to="body">` + `fixed inset-0 z-50` фон + `@click.self="emit('close')"`. Дропдауны (не модалки) типа колокольчика уведомлений — тоже через `Teleport to="body"` с ручным позиционированием по `getBoundingClientRect()`, чтобы не попасть в чужой stacking context (см. баг с `backdrop-filter` у соседних HUD-панелей, из-за которого дропдаун переставал ловить клики).
- **PHPStan уровень 7**: дженерики для `BelongsToMany<TRelated, TDeclaring, TPivot>`, `@property`/`@property-read` докблоки для динамических Eloquent-атрибутов — обязательны.
- **root** как флаг, а не роль — проверяется напрямую (`$user->is_root`) практически во всех policy/controller-проверках доступа.

## 10. Десктопный клиент (Tauri)

Отдельный проект `nodus-desktop/` (соседняя папка, не внутри этого репозитория) — см. его `README.md`. Кратко: это **не** копия приложения с собственным PHP внутри, а тонкое окно на Tauri (Rust + системный `webkit2gtk`), которое открывает работающий сервер как обычный браузер — только без адресной строки, с иконкой в таскбаре.

**Почему так, а не бандл PHP в каждый клиент** — проект по задумке многопользовательский (шеринг, presence, живой синк), поэтому единственная логичная модель — один работающий сервер и много тонких клиентов, а не N независимых изолированных копий на разных машинах.

Статус на этот снимок: локально проверено вживую целиком, оба режима.

- `cargo tauri dev` — открывает нативное окно "Nodus", которое полностью и корректно рендерит живое приложение (HUD, канвас, граф, minimap) с `http://localhost:8000`.
- `cargo tauri build` — production-сборка, даёт `Nodus_0.1.0_amd64.AppImage` (~108 МБ, включает весь GTK/WebKit-рантайм) в `nodus-desktop/src-tauri/target/release/bundle/appimage/`. Запущенный файл распознаётся системным AppImage-тулингом (диалог интеграции), реально открывается и так же корректно рендерит живое приложение — проверено отдельным запуском поверх уже собранного файла, не через `cargo`.

**Была одна проблема при сборке AppImage**, стоит запомнить: `linuxdeploy` (внешний бинарник, который Tauri скачивает для финальной упаковки) падал с `Strip call failed: unknown type [0x13] section '.relr.dyn'` — старый `strip` внутри `linuxdeploy` не понимает секцию `.relr.dyn`, которую генерирует современный тулчейн Arch/CachyOS в `.so`-файлах. Чинится переменной окружения `NO_STRIP=1` (сама она внутри linuxdeploy, не в Tauri-конфиге):
```bash
NO_STRIP=1 npm run tauri build
```
Заодно понадобился `APPIMAGE_EXTRACT_AND_RUN=1`, чтобы `linuxdeploy` (сам являющийся AppImage) надёжно распаковывался и запускался в этом окружении, не полагаясь на прямой FUSE-mount.

Технические детали (CSP, порты, иконка) — см. `nodus-desktop/README.md`, не дублируются здесь.

## 11. Путь к серверу для нескольких машин

Локальный вариант (§10) — сервер и клиент на одном ноутбуке, всё на `localhost`, HTTPS не нужен. Чтобы разные люди могли подключаться с разных машин, нужно расширить именно **серверную** часть — сам Tauri-клиент не меняется концептуально, только URL в его конфиге.

### Что меняется на сервере

1. **Хостинг** — сервер должен быть доступен по сети: либо VPS с доменом, либо домашняя машина/NAS (тогда нужен проброс портов или Dynamic DNS, если IP не статический).
2. **HTTPS обязателен** — без него живые WebSocket-соединения (Reverb, `wss://`) у удалённых клиентов будут рваться или блокироваться браузерным движком (mixed content), и cookie сессии по-хорошему тоже должны идти с флагом `Secure`. Обычно — nginx/Caddy как reverse proxy перед приложением, с сертификатом от Let's Encrypt.
3. **Process manager** — `php artisan serve` не для продакшена. Нужен php-fpm (или FrankenPHP/Laravel Octane) за nginx, плюс `supervisor`/`systemd`, чтобы `reverb:start` не падал и перезапускался сам.
4. **База данных** — уже сделано локально: проект переведён на PostgreSQL (см. `.env`, `DB_CONNECTION=pgsql`) именно из-за многопользовательской записи и лёгкого переноса между серверами через `pg_dump`/`pg_restore`. На реальном сервере остаётся установить и настроить сам PostgreSQL (роль, база, доступ) — конфигурация Laravel уже готова.
5. **Reverb должен быть проброшен наружу** — обычно через тот же reverse proxy, который проксирует `wss://` трафик на порт Reverb (сейчас 8080).
6. **Очередь** — `QUEUE_CONNECTION=database`, но воркер (`php artisan queue:work`) сейчас нигде не запущен (см. §3.4, почему уведомления сознательно этого не требуют). Если в будущем появится что-то, что реально нуждается в очереди — либо переключить на `sync`, либо поднять воркер под supervisor.

### Что НЕ меняется

- Код Laravel/Vue — ноль изменений, вся многопользовательская логика (шеринг, роли, presence) уже реализована и не завязана на то, локальный сервер или удалённый.
- Сам Tauri-клиент — меняется одна строка (`app.windows[0].url`) + origin'ы в CSP на новый адрес сервера, после чего пересобрать.

### Не сделано, если понадобится позже

- Настраиваемый URL сервера прямо в UI Tauri-приложения (сейчас захардкожен на этапе сборки — см. `nodus-desktop/README.md`, "Известные ограничения").
- Собственно сам продакшен-сервер (VPS/домен/nginx/TLS) — на момент этого снимка не разворачивался, обсуждалась только архитектура.
